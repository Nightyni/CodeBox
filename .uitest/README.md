# 前端冒烟检查（不需要浏览器）

后端有 177 个单测，但它们**覆盖不到前端**。这里补一个轻量检查。

## 为什么需要它

曾经出现过一个 bug：`app.js` 里有一处用**裸 id** 调用选择器辅助函数（`$(id)` 而辅助函数要求 `'#id'`），返回 `null`，于是 `null.addEventListener(...)` 在**模块顶层抛异常**。

后果是：**该行之后的所有绑定都没有执行**——「+ 新增」按钮点不动、分隔条拖不动，但页面看起来完全正常（样式、卡片、登录都正常）。后端 177 个测试全绿，`node --check` 也通过。

这类问题只有真正"跑一遍前端代码"才能发现。

## 怎么跑

```powershell
cd .uitest
node harness.js
```

全部通过时输出 `ALL PASS` 并以退出码 0 结束；有任何一项失败则以退出码 1 结束。

## 检查内容

| # | 检查 |
|---|---|
| 1 | `app.js` 模块顶层执行不抛异常（这是最关键的一条） |
| 2 | 所有 `$('#id')` 引用都能在 `index.html` 里找到 |
| 3 | 「+ 新增」能打开弹窗、标题更新、语言下拉已填充 |
| 4 | 「取消」能关闭弹窗 |
| 5 | 分隔条可拖动，比例计算正确（拖到 1000/1600 → 37.5%），松手后**不残留**监听 |
| 6 | 拖动受最小/最大宽度限制（17.5% / 62%） |
| 7 | 「清空」按钮可用 |

## 实现方式

`harness.js` 提供一套**最小 DOM**（`getElementById` / `createElement` / `classList` / 事件派发 / `localStorage`），然后用 `eval` 执行**真实的 `app.js`**，最后对 DOM 状态做断言。

不是浏览器的替代品，但足以抓住"初始化抛异常 / 选择器写错 / 绑定丢失"这一整类问题——这正是它存在的理由。

> 注：本目录只有检查脚本，没有第三方依赖，`npm install` 不是必需的，`node harness.js` 直接即可运行。
